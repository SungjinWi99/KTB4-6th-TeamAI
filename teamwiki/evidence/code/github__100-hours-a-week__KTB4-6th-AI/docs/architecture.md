## 项目概述

本项目（KTB4-6th-AI）是一个面向会议场景的 AI 语音处理后端，用 Python 编写。它接收实时录音，完成音频解码和会话管理，再调用外部 STT 服务做语音转写。转写结果交给部署在 Modal 上的说话人分离（diarization）服务，把每个转写片段对应到具体说话人。最后对会议内容做分析，生成摘要。录音、说话人分离、摘要这三项能力通过 4 个 HTTP 接口对外提供。实时处理和分析的参数由配置模块统一管理，请求日志的上下文由中间件负责。

## 核心链路

### 链路 1：实时录音 → 转写

```
客户端推送音频
  → 请求日志中间件（生成请求上下文）
  → HTTP 录音接口
  → 音频解码（原始音频块 → PCM/可识别格式）
  → 会话管理（按会话 ID 累积音频、维护会话状态）
  → 外部 STT 服务（语音转文字）
  → 转写片段写回会话状态（存在内存中，未发现持久化存储）
  → 返回转写结果
```

### 链路 2：说话人分离

```
客户端请求分离
  → 请求日志中间件
  → HTTP 分离接口
  → 取出会话中的音频和转写片段
  → 调用 Modal Diarization 服务（得到说话人时间段）
  → 按时间对齐，把片段归属到说话人
  → 返回带说话人标签的转写
```

### 链路 3：会议分析 → 摘要

```
客户端请求摘要
  → 请求日志中间件
  → HTTP 摘要接口
  → 读取带说话人标签的转写
  → 会议内容分析（按分析配置参数处理）
  → 摘要生成（具体模型未在索引中说明）
  → 返回结构化摘要
```

> 注：知识索引中没有数据库或对象存储组件，所以三条链路都以"内存会话状态 → 响应返回"结束，没有持久化存储这一步。

## 技术栈

| 维度 | 技术 | 说明 |
|---|---|---|
| 语言 | Python | 由 `pyproject.toml` 管理项目元数据 |
| 依赖 / 构建 | pyproject.toml + 构建后端 | 统一声明运行时依赖、开发依赖和构建配置 |
| Web 接口 | HTTP 服务框架 + 中间件 | 对外提供 4 个 HTTP 接口，由中间件注入请求日志上下文 |
| 语音转写 | 外部 STT 服务 | 以外部服务方式接入，负责实时音频转文字 |
| 说话人分离 | Modal | 在 Modal 上以 Serverless 方式部署 diarization 模型，按需使用 GPU 算力 |
| 音频处理 | 音频解码模块 | 把实时录音流解码为 STT 能处理的格式 |
| 内容分析 | 会议分析 / 摘要模块 | 对带说话人标签的转写做分析并生成摘要 |
| 配置 | 配置管理模块 | 实时处理参数和分析参数分开管理 |
| 可观测性 | 请求日志上下文中间件 | 为每个请求绑定上下文，方便追踪链路日志 |
| 工程工具链 | lint / test / format | 在 `pyproject.toml` 中统一配置 |
